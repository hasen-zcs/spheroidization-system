# 球化监测系统

# 数据库实体说明书

**文档版本：** V1.0
**适用系统：** 球化监测系统
**文档用途：** 明确系统需要持久化的数据实体、实体职责及实体之间的关系，为后续数据库表设计提供依据。

---

## 1. 文档目的

本文档用于说明球化监测系统中需要长期保存的核心业务数据。

数据库设计应以本文档定义的业务实体为基础进行，不直接根据前端页面或当前 Mock 数据结构创建数据库表。

当前系统数据库只设计核心业务数据，不提前设计暂未进入系统业务范围的实体。

---

# 2. 核心数据实体

当前系统确定包含以下三个核心实体：

| 实体                    | 说明     |
| --------------------- | ------ |
| StandardRecord        | 检测标准记录 |
| SpheroidizationRecord | 球化检测记录 |
| ReviewRecord          | 人工复核记录 |

实体关系：

```text
StandardRecord
      │
      │ 检测时保存标准快照
      ↓
SpheroidizationRecord
      │
      │ 1 : N
      ↓
ReviewRecord
```

---

# 3. StandardRecord——检测标准记录

## 3.1 实体说明

`StandardRecord` 用于保存系统中的检测标准。

每当工作人员创建一个新的检测标准时，系统新增一条 StandardRecord。

新创建的标准立即成为当前有效标准。

历史标准不删除、不覆盖，用于保留检测标准的历史变化。

---

## 3.2 主要职责

StandardRecord 负责：

1. 保存当前检测标准。
2. 保存历史检测标准。
3. 记录标准的创建人和创建时间。
4. 记录标准调整原因或备注。
5. 为新的球化检测记录提供检测标准。
6. 支持查询当前标准和历史标准。

---

## 3.3 核心数据

```text
StandardRecord
├── id
├── standard_spheroidization_time
├── standard_entry_length
├── weighing_standard
├── created_at
├── created_by
└── remark
```

---

## 3.4 标准生效规则

系统不单独维护一个“当前标准”对象。

当前标准定义为：

```text
最新创建的 StandardRecord
```

例如：

```text
ID    球化时间    入料长度
1       60          120
2       65          125
3       70          130
```

则 ID = 3 的 StandardRecord 为当前有效标准。

当工作人员创建新的标准：

```text
ID = 4
```

ID = 4 创建成功后立即成为当前标准。

---

## 3.5 历史标准规则

历史标准必须保留。

修改标准的业务行为实际上是：

```text
创建一条新的 StandardRecord
```

而不是：

```text
修改原来的 StandardRecord
```

因此：

```text
旧标准 → 保留
新标准 → 新增
新标准 → 立即生效
```

---

# 4. SpheroidizationRecord——球化检测记录

## 4.1 实体说明

`SpheroidizationRecord` 是系统最核心的业务实体。

一条 SpheroidizationRecord 表示：

> 一次已经完成的球化检测结果。

业务系统不记录检测过程中的“进行中”状态，只接收检测模块已经完成的检测结果。

---

## 4.2 数据来源

SpheroidizationRecord 的主要数据来源为上游检测模块。

检测模块完成检测后，将最终检测结果提供给业务系统。

当前阶段不定义检测模块与业务系统之间的具体通信协议。

业务系统只保留：

```text
检测模块
    ↓
完整检测结果
    ↓
SpheroidizationRecord
```

---

## 4.3 主要职责

SpheroidizationRecord 负责：

1. 保存一次完整球化检测结果。
2. 保存铁水重量等检测数据。
3. 保存机器检测结果。
4. 保存异常判断结果。
5. 保存检测时使用的标准快照。
6. 保存工作人员的处理状态。
7. 为人工复核提供业务对象。

---

## 4.4 核心数据

```text
SpheroidizationRecord
├── id
│
├── detection_time
├── iron_water_weight
│
├── spheroidization_start_time
├── spheroidization_end_time
├── actual_spheroidization_time
├── actual_entry_length
│
├── machine_result
├── spheroidization_abnormal
├── entry_abnormal
│
├── standard_spheroidization_time
├── standard_entry_length
├── weighing_standard
│
├── processed
├── processed_at
└── processed_by
```

---

# 5. 检测标准快照

## 5.1 为什么需要标准快照

球化检测记录必须保存检测发生时使用的检测标准。

不能只保存：

```text
standard_id
```

然后始终从当前 StandardRecord 查询标准。

原因是检测标准会发生变化。

例如：

```text
9月1日
标准：60秒 / 120mm

9月5日
标准：70秒 / 130mm

9月10日
标准：80秒 / 140mm
```

如果 9 月 1 日的历史记录只依赖当前标准，那么未来无法准确还原当时使用的标准。

---

## 5.2 快照规则

创建 SpheroidizationRecord 时：

```text
获取当前 StandardRecord
        ↓
复制当前标准参数
        ↓
保存到 SpheroidizationRecord
```

保存：

```text
standard_spheroidization_time
standard_entry_length
weighing_standard
```

因此：

```text
StandardRecord
       ↓
   检测时复制
       ↓
SpheroidizationRecord
```

---

## 5.3 历史独立性

检测记录创建后，StandardRecord 再发生变化，不影响已经存在的 SpheroidizationRecord。

例如：

```text
检测记录 A
使用标准：70 / 130

后来标准修改为：
80 / 140
```

检测记录 A 仍然保存：

```text
70 / 130
```

---

# 6. SpheroidizationRecord——处理状态

## 6.1 处理状态说明

系统允许工作人员独立标记球化检测记录是否已经处理。

处理状态属于 SpheroidizationRecord 本身。

当前不建立独立的 `ProcessRecord` 实体。

---

## 6.2 处理数据

```text
processed
processed_at
processed_by
```

含义：

| 字段           | 含义     |
| ------------ | ------ |
| processed    | 是否已经处理 |
| processed_at | 处理时间   |
| processed_by | 处理人    |

---

## 6.3 处理规则

处理状态与人工复核状态相互独立。

即：

```text
复核完成 ≠ 处理完成
```

工作人员可以：

```text
不进行人工复核
      ↓
直接标记已处理
```

也可以：

```text
人工复核
      ↓
标记已处理
```

---

# 7. ReviewRecord——人工复核记录

## 7.1 实体说明

`ReviewRecord` 用于保存工作人员对球化检测记录进行人工复核产生的结果。

人工复核不能修改原始机器检测结果。

---

## 7.2 主要职责

ReviewRecord 负责：

1. 保存人工复核结果。
2. 保存人工复核说明。
3. 保存复核人员。
4. 保存复核时间。
5. 保存与球化检测记录之间的关联。

---

## 7.3 核心数据

```text
ReviewRecord
├── id
├── spheroidization_record_id
├── review_result
├── review_remark
├── reviewer
└── reviewed_at
```

---

# 8. 机器检测结果与人工复核结果

系统必须明确区分：

```text
机器检测结果
```

和：

```text
人工复核结果
```

两者不能互相覆盖。

例如：

```text
机器检测结果：异常

人工复核结果：正常

复核说明：
检测过程中存在短暂光照波动，
实际球化效果正常。
```

数据库中应当保留：

```text
SpheroidizationRecord
machine_result = 异常

ReviewRecord
review_result = 正常
review_remark = ...
```

而不能将：

```text
machine_result
```

直接修改为：

```text
正常
```

---

# 9. ReviewRecord 与 SpheroidizationRecord 的关系

两者之间为：

```text
SpheroidizationRecord 1 : N ReviewRecord
```

即：

> 一条球化检测记录可以对应多条人工复核记录。

例如：

```text
球化记录 #100
    │
    ├── 复核记录 #1
    ├── 复核记录 #2
    └── 复核记录 #3
```

当前系统不要求 ReviewRecord 被修改或删除。

人工复核操作原则上是：

```text
新增 ReviewRecord
```

而不是覆盖历史复核记录。

---

# 10. 三个实体之间的完整关系

```text
┌─────────────────────────┐
│    StandardRecord       │
│       检测标准           │
└────────────┬────────────┘
             │
             │ 检测时生成标准快照
             ↓
┌─────────────────────────┐
│ SpheroidizationRecord   │
│       球化检测记录       │
│                         │
│ 机器检测结果             │
│ 检测数据                 │
│ 标准快照                 │
│ 处理状态                 │
└────────────┬────────────┘
             │
             │ 1 : N
             ↓
┌─────────────────────────┐
│      ReviewRecord       │
│       人工复核记录       │
└─────────────────────────┘
```

# 11. 当前暂不建立的数据实体

为了避免过度设计，当前版本暂不建立以下实体：

```text
User
ProductionLine
Device
Camera
Permission
OperationLog
ProcessRecord
```

原因是这些实体目前不属于已经确定的核心业务边界。

未来业务需要时再增加。

---

# 12. 数据不可变规则

系统中存在两类数据。

## 12.1 机器事实数据

由检测模块产生：

```text
detection_time
iron_water_weight
actual_spheroidization_time
actual_entry_length
machine_result
spheroidization_abnormal
entry_abnormal
```

以及检测时使用的：

```text
standard_spheroidization_time
standard_entry_length
weighing_standard
```

这些数据创建后原则上不可被工作人员修改。

---

## 12.2 人工业务数据

工作人员可以产生：

```text
ReviewRecord
```

以及修改：

```text
processed
processed_at
processed_by
```

人工判断和处理信息以追加或独立状态的方式保存，不覆盖机器原始事实。

---

# 13. 数据实体设计原则

当前数据库设计遵循以下原则：

### 原则一：只保存核心业务数据

当前只确定：

```text
StandardRecord
SpheroidizationRecord
ReviewRecord
```

---

### 原则二：机器事实不可篡改

机器检测结果与人工复核结果分离。

---

### 原则三：标准保留历史

新标准通过新增记录产生，不覆盖旧标准。

---

### 原则四：检测记录保存标准快照

保证历史检测数据与未来标准变化相互独立。

---

### 原则五：处理状态独立于复核

```text
复核 ≠ 处理
```

两者分别管理。

---

### 原则六：不提前设计不存在的业务

数据库不因为“以后可能需要”而提前增加大量实体。

---

**当前版本数据库实体数量：3 个。**

```text

  ↓

  ↓

  ↓

  ↓

```

数据库具体实现不属于本实体说明书的范围。
