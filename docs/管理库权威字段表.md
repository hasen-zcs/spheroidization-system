## 二、上游 → 管理库 映射表

约定：**必须转换** = 上游原样值直接发接口会被 422 / 落错型 / 违反 CHECK，合并层必须改。
"缺失时怎么办"指该上游字段为 null/不存在时管理库怎么落。

### A. 检测 reactions.jsonl（样例 reactions.raw.jsonl / reactions.slim.jsonl，40 行；7 个原生字段 + 3 个扩展字段）

| 上游字段 | 上游类型/样例 | 映射到管理库字段 | 需要转换？ | 转换规则 | 缺失时怎么办 |
|---|---|---|---|---|---|

| detection_time | str `"2026-11-01 08:57:43.092"` | SpheroidizationRecord.detection_time | 不需要 | 原样（带毫秒格式接口收） | 必填，缺则整条 422 |

### 必须转换项汇总（8 项）

1. `actual_spheroidization_time`：`"00:01:28.40"` → REAL 秒 `88.40`（3 位小数）
2. `spheroidization_abnormal`：`"成功"`→0 / `"失败"`→1 / `"未判定"`→null（**成功=0**，null≠0）
3. `spheroidization_image`：剥 `data:image/jpeg;base64,` 前缀 → base64 解码 bytes
4. `spheroidization_segments`：`seq/start/end/duration_sec/gap_before_sec`（墙钟）→ `seg_index/start_offset/end_offset/duration/gap_before`（相对首段起点秒，3 位小数，首段 gap_before=null、start_offset=0）
5. `device_name` `"2026-11-01 测温枪4"` → `gun_no=4`
6. `spheroidization_temperature` 字符串 `"1419"` → REAL 1419.0
7. `reaction_count` int → external_id 字符串；**三套独立计数（检测/PLC/温度各自编号），禁止跨源配对**
8. 毫秒时间串 → 温度 `measured_at` 必须截成 `YYYY-MM-DD HH:MM:SS`（球化主表字段两种格式都收，可不截）

## 三、冲突与缺口

### 3.1 上游有、管理库没有的字段（处置建议：丢弃/待扩展，**不擅自加库字段**）

| # | 上游字段 | 出处 | 处置建议 |
|---|---|---|---|
| 1 | `plc_arrival_time` | heat_records（样例 60 行恒为 null） | 丢弃；当前无实际数据量，若后续有值再走变更流程"待扩展" |
| 2 | `plc_anchor`（"button"/"light_start"） | heat_records | 丢弃，合并层日志留痕；库的 detection_time/plc_button_time 已各自留了原始时刻 |
| 3 | `source`（"plc"/"csv"） | plc.jsonl / temperature.jsonl | 并入 device_id（plc 源）或丢弃（温度源） |
| 4 | 上游 `created_at`（plc/温度事件时刻） | plc.jsonl / temperature.jsonl | 丢弃：库内 created_at 均为"入库时间"，服务端生成，语义不同 |
| 5 | `reaction_count` 作为主表数据 | 三源 | 只进 UploadLedger.external_id（球化主链路）；温度源无台账列，仅供合并层内部去重 |
| 6 | segments 的 `start`/`end` 原墙钟值 | heat_records | 不存：可用 记录 spheroidization_start_time + start/end_offset 无损还原 |
| 7 | `device_name` 全串（含日期前缀） | temperature.jsonl | 只存 gun_no；日期前缀丢弃 |
| 8 | 图片的 `data:image/jpeg;base64,` 头 | reactions | 不存：库只存纯二进制 BLOB |

### 3.2 管理库必填（NOT NULL）、上游不给的字段（🔴 合并层/服务端责任）

| # | 库字段（NOT NULL） | 上游来源 | 🔴 责任方与缺口 |
|---|---|---|---|
| 1 | SpheroidizationRecord.standard_record_id (L18) | 无 | 服务端 `_build` 从当前生效标准取；**库里没有任何生效标准时建档直接失败**——合并层要能识别该 400 并重试/告警，不能丢数据 |
| 2 | SpheroidizationRecord.standard_spheroidization_time (L23) 快照 | 无 | 同上，服务端快照；合并层不传也不该传 |
| 3 | SpheroidizationRecord.processed (L29) | 无 | 服务端固定 0；processed_at/by 走 CHECK 联动，合并层不得在建档时塞处理人 |
| 4 | SpheroidizationRecord.detection_time (L19) | 仅 heat/reactions 有；**PLC 源没有** | 🔴 只有 PLC 数据时建不了档，必须等 heat 记录带齐 detection_time + 4 个 PLC 字段；heat 缺 PLC 4 字段时用 PLC 源按时间补 |
| 5 | SpheroidizationRecord 4 个 PLC 字段 (L32-L35) | 仅 PLC 源/heat 有；**reactions 源没有** | 🔴 纯检测记录（reactions.jsonl）缺这 4 个必填项，直接建档必 422；必须与 PLC 源合并（按时间就近配对，**不按 reaction_count，两套编号独立**） |
| 6 | TemperatureRecord.gun_no / temperature / measured_at (L56-L58) | 温度源 | 🔴 三项缺任一即整条拒收（gun_no 剥不出数字、温度非数值、时间带毫秒未截断都是常见失败点） |
| 7 | TemperatureRecord.created_at (L60) | 不采上游 | 服务端生成 |
| 8 | UploadLedger 全部 6 列 (L106-L111) | 半有半无 | 🔴 device_id 由合并层约定指定；external_id=reaction_count 转 str；record_id/payload_sha/created_at 服务端生成。device_id+external_id **必须成对**，只给一个 422 |
| 9 | FlashSegment 各 NOT NULL 列 | segments | 🔴 换算误差 >20ms（duration/首段 offset=0/末段=跨度/gap 对不上）整条 422；type=5 幂等路径 <2 段 422 |

### 3.3 其他口径冲突（不改库，合并层消化）

- **reactions 源 spheroidization_abnormal 是中文串，heat 源是 0/1 int**——同一字段两种形态，合并层统一按转换项 2 归一成 int/None 后再发。
- **温度无法走幂等台账**（TemperatureRecord 无 (device_id, external_id) 列）：温度重复推送的判重只能靠 (gun_no, measured_at) 业务唯一性检查，属合并层责任；如需库级幂等属"待扩展"，不在本次范围。
- **按钮文件无流水号**：button.jsonl 只有一列时间，与 heat 的 plc_button_time 靠时间就近配对（秒级对齐，实测一一对应）。
- **ReviewRecord / StandardSwitchLogs / UserAccount / UserPermission**：无上游来源，纯人工/登录态产生，合并层不碰。
