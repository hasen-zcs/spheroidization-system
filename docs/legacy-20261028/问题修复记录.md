## 一、修复清单

### 1. 新增球化记录失败

**原问题**

前端新增表单只提交 5 个旧字段，后端要求温度、测温时间、进线起止时间、进线总时长和重量，实际返回业务码 `422`。

**修复内容**

- 前端 `CreateSpheroidizationInput` 改为完整的后端必填字段。
- 新增记录页面补齐温度、测温时间、进线开始时间、进线结束时间、进线总时长、球化重量输入框。
- 后端请求模型使用 `extra="forbid"`，旧字段或未知字段不再静默忽略。

**涉及文件**

**原问题**

- 列表和详情页增加错误状态。
- 后端增加 `sqlite3.IntegrityError` 统一响应处理，避免数据库约束错误泄漏成普通 500 文本。

## 五、备注
### 标准应用状态（方案一）

数据库表结构保持不变。当前应用标准 ID 保存到 `data/active_standard.json`。
新建标准后自动更新该文件；历史标准可以通过“应用标准”按钮重新应用。

外部获取接口不变：

- `GET /api/standards/current`
- `GET /api/standards/history`

只有主动切换标准时调用 `POST /api/standards/{standard_id}/apply`。
读取时优先使用应用状态文件；文件缺失或 ID 无效时兼容回退到最大标准 ID。

验证结果：`57 passed`，前端 `npm run build` 通过。

端到端切换测试记录：

- 创建测试标准 ID 2、3。
- 应用到旧标准 ID 1：`POST /api/standards/1/apply` 返回 `code 200`，`GET /current` 返回 ID 1。
- 切换到测试标准 ID 3：应用接口返回 `code 200`，`GET /current` 返回 ID 3。
- 再切换到测试标准 ID 2：应用接口返回 `code 200`，`GET /current` 返回 ID 2。
- 重启后端后再次调用 `GET /api/standards/current`，仍返回 ID 2，持久化验证通过。
- `data/active_standard.json` 中记录的 `standard_record_id` 为 2。

### 删除后 ID 序列回退

为三张使用 AUTOINCREMENT 的表增加 AFTER DELETE 触发器：

- `standard_sync_sequence`
- `spheroidization_sync_sequence`
- `review_sync_sequence`

触发器使用当前表的 MAX(id) 更新 sqlite_sequence，不用 COUNT(*)：

- 删除中间行：最大 ID 不变，新 ID 继续加一。
- 删除最后一行：序列回退，新数据复用被删除的最后一个 ID。
- 删除全部数据：序列为 0，下一条从 ID 1 开始。

已有数据库启动时会自动补触发器。验证结果：`62 passed`，当前数据库三条触发器均已创建。

新增 `API接口总览.md`，整合全部接口、请求字段、响应字段、错误码和业务规则。
